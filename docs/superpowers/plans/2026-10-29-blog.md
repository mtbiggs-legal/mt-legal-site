# Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public `/blog` that gets one AI-drafted post a week. Each draft is emailed to the attorney, who can publish, edit or pull it. A draft publishes on its own 48 hours after the email goes out. The blog has an RSS feed, sitemap entries and JSON-LD.

**Architecture:** Two domain modules at the top level, like `billing.py`. `blog.py` handles storage, the body format, review tokens and rotation. `blog_writer.py` handles the Claude prompt, validation and the review email. A third module, `blog_scheduler.py`, has an hourly `tick()` that runs on a daemon thread. The routes live in `blueprints/blog.py` under `/blog/...`, which `PUBLIC_SITE_ONLY` never blocks. Posts are JSON files in `DATA_ROOT/blog/`. Launch posts and starter topics ship in `blog_seed/` and are merged in at startup.

**Tech Stack:** Flask, Jinja, `itsdangerous` (ships with Flask), Anthropic SDK, SendGrid through `email_service._send`, pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-blog-design.md`

## Global Constraints

- Blog areas only: `criminal-defense`, `stablecoins`, `rwa-tokenization`, `civil-rights`, `estate-business`. Family law and personal injury are left out on purpose.
- Rotation: criminal defense → crypto → civil rights → estate planning. Crypto alternates `stablecoins` and `rwa-tokenization`. Formats rotate `article` → `qa` → `tips`.
- Review window: 48 hours, counted from when the review email is **actually sent**. Tokens expire after 7 days.
- No email sent means no auto-publish. The tick retries the email every time.
- Pulled or failed weeks still advance the rotation. A pulled post's topic goes back into the queue as unused. At most one generated post per ISO week.
- Copy rules: no public-defender mentions, no promises of results, no wording that implies more than one attorney, no uncertain citations, 600–1,000 words.
- `BLOG_AUTOGEN` defaults to off, and `render.yaml` turns it on. `BLOG_MODEL` defaults to `claude-sonnet-5-5`.
- Every route gets `@require_auth` from `shared` (the share-password gate), like the other public routes. JSON routes return `{"success": True}` / `{"error": ...}`. Templates escape everything. Post bodies never go through `|safe`.
- New CSS goes at the bottom of `static/css/style.css` and uses theme variables.
- Tests use the `conftest.py` fixtures. They never call the real Anthropic or SendGrid, and they never touch the real `blog/` folder.
- Commit messages use the conventional scopes (`feat(blog): ...`). Stage specific files only.

## Review Focus

1. **A mail scanner prefetches the email links.** A GET must never publish or pull anything. → Task 4 `test_get_publish_link_changes_nothing`.
2. **Generation succeeds but the email fails, and the server restarts.** On the next tick the draft must still be unpublished and the email retried, not lost. → Task 6 `test_unsent_draft_never_publishes_and_email_retried`.
3. **Model output smuggles HTML or script into the title or body.** It must render as text. → Task 2 `test_post_body_html_is_escaped`.
4. **An old or edited token is reused.** A token for post A must not act on post B, and a pulled post's link must be dead. → Task 4 `test_token_bound_to_one_post` and `test_pulled_post_links_dead`.
5. **Two ticks run at once** (4 threads, or the dev reloader). Exactly one draft per week. → Task 6 `test_concurrent_ticks_make_one_draft`.

---

**Deferred from the spec:** the latest posts on each practice page (the spec marks it nice-to-have) and rate limiting on the review routes (the tokens are signed, expire, and are bound to one post).

### Task 4: Review tokens and review routes

**Files:**

**Interfaces:**
- `blog.make_review_token(post: dict) -> str`. `URLSafeTimedSerializer(current_app.secret_key, salt="blog-review")` signs `{"s": slug, "r": review_token_id}`.
- `blog.REVIEW_TOKEN_MAX_AGE = 7*24*3600` (seconds). `blog.read_review_token(token: str) -> dict | None` reads it at call time as `max_age`. Returns the post only if the signature is valid, the token hasn't expired, the post exists and `r` matches. Otherwise returns None.
- `blog.publish(slug: str, now: datetime | None = None) -> bool`: draft → published, sets `published_at`. Returns False if the post isn't a draft.
- `blog.pull(slug: str) -> bool`: draft → pulled, and its topic goes back to `used=False`. Returns False if the post isn't a draft.
- `blog.update_post(slug, title, summary, body) -> dict`: trims the fields, rejects an empty title or body with `ValueError`, sets `updated_at`, and leaves `publish_at` alone.
- Routes (all under `/blog/review/`, all `@require_auth`, all sending `X-Robots-Tag: noindex` and a `<meta name="robots" content="noindex">`):
  - `GET /blog/review/<token>/<action>` with `action` in `publish|pull` → `blog.review_confirm`. It renders `blog_action.html` with the post title, a sentence saying what will happen, and a POST form with `csrf_token()`. It changes nothing.
  - `POST /blog/review/<token>/<action>` does the change and renders `blog_action.html` with the result ("Published." / "Pulled. Nothing goes up this week." / "This draft was already published or pulled.").
  - `GET /blog/review/<token>` → `blog.review_edit`. Shows the title, summary and body (the raw text) fields, buttons for `op` = `save` | `publish` | `pull`, and a separate "Add a topic idea" form (area `<select>` over `BLOG_AREAS`, title, `op=add_topic`).
  - `POST /blog/review/<token>` handles `op`. On a published post, `save` is allowed (a typo fix until the token expires), and `publish`/`pull` are not. On a pulled post, everything returns 410.
  - An invalid or expired token returns 404 with `blog_action.html` saying "This review link has expired or is no longer valid."

- `tick(app, now: datetime | None = None) -> None`. Runs inside `app.app_context()`. Takes a lock with `os.open(BLOG_DIR / ".tick.lock", O_CREAT | O_EXCL)`, deleting the lock file first if it's older than `LOCK_STALE_SECONDS`. If the lock is held, it returns immediately. The lock is released in `finally`. Then, in this order:
  1. **Drafts.** For each `draft`: if `review_email_sent_at` is None, try `send_review_email`. On success, set `review_email_sent_at = now` and `publish_at = now + REVIEW_WINDOW`, then save. Otherwise, if `publish_at <= now`, call `blog.publish`.
  2. **Weekly draft.** Only if `shared.BLOG_AUTOGEN`. Let `state = load_state()` and `wk = iso_week(now)`. If `state["week"] == wk`, stop. Otherwise reset `attempts` to 0 if the stored attempts were for a different week (store `attempts_week` alongside). Then:
     - Set `area = ROTATION[step % 8]`, `fmt = FORMATS[step % 3]` and `topic = next_topic(area)`.
     - Call `generate_post(area, fmt, topic and topic["title"], [p["title"] for p in list_posts()])`.
     - On success: `new_post(..., topic_id=topic and topic["id"])`, then `save_post`, mark the topic used, set `step += 1` and `week = wk`, save the state, and immediately try the email as in step 1.
     - On `BlogGenerationError`: increment `attempts`, log it, and if `attempts >= MAX_ATTEMPTS`, set `step += 1` and `week = wk` (the week is given up). Save the state.
  - Every exception is caught and logged, so the thread never dies.
- `start_scheduler(app) -> threading.Thread`. A daemon thread that loops `tick(app)` then `time.sleep(TICK_SECONDS)`. It's started once per process (a module-level guard).
